# Orbiter 設計思想 (Design Philosophy)

## 1. 核心となるビジョン
**「思考の分断をゼロにする、究極の統合ワークスペース」**

開発者やパワーユーザーにとって、ファイル管理とコマンド実行は切り離せない一連の動作です。
Windows標準のエクスプローラーとターミナルを別々に立ち上げ、ウィンドウを切り替えながら作業する現状は、思考のフローを分断させる非効率なものです。
Orbiterは、これらを1つの画面にシームレスに統合することで、直感的な操作と高速なワークフローを実現します。

## 2. デザインの三原則

### I. シングルウィンドウ完結 (One-Window Focus)
すべての主要なツール（ファイラー、ターミナル、プレビュー）を1つのウィンドウ内に配置します。
ユーザーが「今何をしているか」を常に把握でき、最小限の視線移動で必要な情報にアクセスできる状態を理想とします。

### II. 高速なレスポンス (Instant Performance)
デザインの美しさだけでなく、ツールとしての「道具感」を重視します。
C言語によるバックエンド処理を活用し、膨大なファイル群もストレスなく扱える軽快さを提供します。

### III. 道具を自分に合わせる (Personalization)
ユーザーごとに最適な作業環境は異なります。
テーマカスタマイズ、ビューモードの柔軟な切り替え、ショートカットによる操作など、アプリがユーザーに合わせる柔軟性を持ちます。

## 3. マルチウィンドウ機能の再定義
実装されたマルチウィンドウ機能は、設計思想に反するものではなく、以下の役割を持つ**「拡張（Extension）」**として定義します。

- **補助的な空間**: メインのシングルウィンドウ体験を補完するための「一時的な作業領域」または「サブモニター用」の機能です。
- **ワークフローの柔軟性**: 設計思想の追求が「不便」に繋がってはいけません。基本は1ウィンドウで完結させるUIを提供しつつ、ユーザーが必要とした時にのみ門戸を開く、いわば「脱出口（Escape Hatch）」としての位置付けです。

## 4. 目指すべき未来
Orbiterは単なる「ファイル管理ソフト」ではなく、開発者がPCを開いた時に最初に立ち上げ、そのまま一日中閉じずに作業を完結させられる「ホームグラウンド」を目指します。
